# 3강. MCP x Verse 게임플레이 루프 : 타임어택 & 매치 시스템

> 처음 계획안을 **지금 만들어진 게임(FallGuys_Sample) 기준**으로 다시 쓴 것입니다.
> 계획과 달라진 점은 맨 아래 "계획 대비 달라진 점"에 따로 모았습니다.

---

## 1. 학습 목표

- 1~2강에서 배치한 체크포인트, 결승선, 장애물에 **실제 Verse 로직을 연결**한다 (진행도 집계, 골인 판정, 튕김, 효과음)
- 제한 시간 5분 **타임어택 카운트다운**과 **플레이어별 골인 기록** 시스템을 구현한다
- 모든 플레이어의 골인 또는 시간 종료로 **매치를 끝내고, 순위와 걸린 시간을 보여주는 결과 화면**을 완성한다
- MCP가 **만들고 → 컴파일 → 로그로 검증**하는 반복(개발 루프)을 직접 경험한다

## 2. 핵심 가치

승패 판정, 기록, 순위, 사운드/화면 피드백까지 갖춘 **"플레이 가능한 게임"으로 완성**한다.
장치만으로는 어려운 규칙(플레이어별 골인 순서, 실시간 순위, 마지막 10초 알람)을 Verse로 채우는 경험을 한다.

## 3. MCP 활용 세부 내용

- MCP가 `find_actors`로 레벨의 체크포인트, 장애물, 결승선 장치를 **이름으로 조회**하고, Verse 장치의 `@editable` 칸에 **자동으로 연결**
  - 배열은 API로 만들 수 없어서, 장치마다 칸을 따로 만들고 연결하는 방식을 사용
- 플레이어별 상태를 `[player]` 맵으로 관리하는 코드를 MCP가 설계, 작성
  - 체크포인트 개수 `[player]int`, 골인 순위/남은 시간/걸린 시간 `[agent]int`
- 라운드 종료 조건(시간 초과 또는 전원 골인)과 순위 계산 로직을 MCP가 작성하고 **`BuildAll`로 컴파일 검증**
- 플레이 결과는 MCP가 **로그(`GetLogEntries`)로 확인**하고, 소리와 화면은 녹화 파일을 분석해서 확인
  - MCP는 게임을 직접 보거나 들을 수 없다는 한계도 함께 배운다

## 4. 학습 결과물

- 타임어택 카운트다운 + 플레이어별 골인 기록 시스템
- 체크포인트 진행도와 현재 순위(`1ST / 4`)를 보여주는 실시간 HUD
- 매치 종료 시 순위와 걸린 시간(또는 `TIME OVER!`)을 보여주는 결과 화면
- 이벤트별 사운드(시작 GO, 체크포인트, 튕김, 리스폰, 낙사, 바람, 마지막 10초 알람, 골인, 타임오버)와 배경음악
- 1~3강을 통해 완성된 게임

---

## 게임플레이 루프 구성도

1. **race_manager** (`creative_device`) — 레이스 전체 진행
   - 카운트다운 타이머: 라운드 시작과 함께 5분을 세고, 0이 되면 레이스를 끝냄
   - 골인 감지: 결승 아치 구역에 들어온 플레이어를 0.05초마다 확인, 골인 순간 순위, 기록 저장
   - 체크포인트 진행도: 체크포인트 4개의 "처음 밟음" 이벤트로 플레이어별 개수 집계
   - 실시간 순위: 골인한 사람 → 체크포인트 개수 → 코스 앞쪽 위치 순서로 계산
   - 마지막 10초 알람, 결과 화면, 게임 종료
2. **체크포인트 패드 4개** (`player_checkpoint_device`)
   - 낙사 후 리스폰 위치를 마지막으로 밟은 패드로 갱신하는 일은 **장치 기본 기능**이 담당
   - Verse는 "몇 번째를 밟았는지"만 세서 HUD에 보여줌
3. **flipper_knockback** — 플리퍼, 기둥, 주먹 튕김
   - 플레이어와 장애물의 거리를 틱마다 검사해서, 닿으면 바운서를 발밑으로 보내 튕김
4. **seesaw_controller** — 시소 2개와 위에 올린 범퍼 기둥 8개
   - 시소를 사인 곡선으로 기울이고, 기둥이 시소 중심을 돌며 닿으면 튕김
5. **sfx_manager** — 리스폰, 낙사, 체크포인트, 에어벤트 바람 소리
   - 플레이어 "살아있음/쓰러짐" 상태 변화와 바람 구역 진입을 감지해서 소리 재생
6. **결과 화면 / HUD** — `race_manager` 안에서 구성
   - 위: 타이머와 체크포인트 줄, 왼쪽 아래: 순위, 화면 전체: 결과(이탤릭 글자 이미지)

## 강의 상세 워크플로우

### 1) 장치 조회 및 Verse 장치 연결
- **실습내용**: MCP가 `find_actors`로 체크포인트, 결승선 장치를 찾아, `race_manager`의 `Checkpoint1~4` 등 `@editable` 칸에 자동 연결
- 확인: 연결 후 값을 다시 읽어서 제대로 들어갔는지 검증

### 2) 플레이어별 상태 추적 자료구조 설계
- **실습내용**: `[player]int`(체크포인트 개수), `[agent]int`(골인 순위, 남은 시간, 걸린 시간) 맵을 쓰는 코드를 MCP에게 작성 요청 → `VerseToolset.WriteFile`로 파일 생성
- 핵심 포인트: 플레이어가 나가고 들어와도 맵이 깨지지 않게 다루는 법

### 3) 타임어택 타이머와 골인 로직 작성
- **실습내용**: 카운트다운 타이머와 결승선 감지를 연결해서, 골인하면 그 플레이어의 시간을 정지하고 기록 저장 → `BuildAll`로 컴파일 검증
- 핵심 포인트: 골인 순간의 시간과 결과 화면의 시간이 같아야 하므로 한 곳에서 계산

### 4) 체크포인트 진행도와 낙사 처리 연결
- **실습내용**: 체크포인트 "처음 밟음" 이벤트를 구독해서 진행도를 집계하고, 낙사는 체크포인트 장치 기본 리스폰으로 처리, 죽음/리스폰 소리는 상태 변화 감지로 재생
- 핵심 포인트: 장치가 해주는 일과 Verse가 해야 할 일을 구분하기

### 5) 매치 종료와 결과 화면
- **실습내용**: 종료 조건(시간 초과 또는 남은 플레이어 모두 골인)을 판정하고, 순위와 걸린 시간을 보여주는 결과 화면을 구성한 뒤 End Game 장치를 작동
- 핵심 포인트: 시간 초과 시 골인 못한 사람은 `TIME OVER!`, 골인한 사람은 순위와 시간

### 6) 사운드와 HUD 마무리
- **실습내용**: 직접 만든 효과음 wav를 가져와 Audio Player에 연결하고 `Play(Agent)`로 재생, 마지막 10초 알람과 왼쪽 아래 순위 HUD 추가
- 핵심 포인트: 라이브러리 소리와 직접 가져온 소리의 차이, 플레이어별로 들리게 하는 설정

### 7) 통합 플레이테스트
- **실습내용**: 1~3강에서 만든 전체 게임을 처음부터 끝까지 플레이 → 장애물, 체크포인트, 타이머, 순위, 소리 전 과정 검증
- 가능하면 **2명 이상**으로 진행해서 순위와 결과 화면 확인
- 로그와 녹화로 문제를 찾고 MCP에게 수정 요청하는 반복을 마지막에 한 번 더 경험

## 계획 대비 달라진 점

| 처음 계획 | 지금 만들어진 것 | 이유 / 메모 |
|---|---|---|
| `checkpoint_tracker`가 마지막 체크포인트를 `[player]transform`에 저장, 낙사 시 `Respawn()` | **장치 기본 기능**이 리스폰을 처리, Verse는 진행도 개수만 집계 | 체크포인트 장치가 이미 해주는 일이라 코드가 필요 없음 |
| `race_timer`가 `race` 표현식으로 "완주 vs 시간 초과" 경쟁 | 타이머 루프가 0.2초마다 남은 시간을 확인하고, 0이 되면 `EndRace` 호출 | 플레이어별로 따로 골인해서 한 번의 `race`로 표현하기 어려움 |
| `finish_line_trigger`가 결승선 감지 | `race_manager`가 아치 구역(상자)을 직접 감지 | 트리거 장치의 감지 범위가 작아서 놓치는 경우가 있었음 |
| `match_manager`가 전체 서브시스템을 초기화 | `race_manager` **한 파일**이 레이스 전체를 담당 (+ 효과음, 장애물은 별도 파일) | 파일이 4개(`race_manager`, `flipper_knockback`, `seesaw_controller`, `sfx_manager`) |
| `leaderboard_hud`가 완주 시간을 정렬해 HUD에 순위 표시 | **결과 화면**(내 순위와 걸린 시간) + **실시간 순위 HUD**(`1ST / 4`) | 전체 순위표는 플레이어 이름을 Verse에서 읽을 수 없어 뺐음 |
| 없음 | 배경음악, 이벤트별 효과음 10종, 마지막 10초 알람 | 게임 완성도를 위해 추가 |
| 없음 | 시소와 범퍼 기둥, 주먹, 플리퍼 튕김 | 1~2강의 장애물에 동작을 입힘 |

## 수업 운영 시 참고 (불특정 인원 대상 온라인 강의)

- **1~3강은 하나의 시리즈입니다**: 수강생은 1~2강에서 만든 맵을 그대로 이어서 3강을 진행합니다. 그래서 3강 첫머리에 "1~2강 결과물 점검"(체크포인트 4개, 결승선, 장애물이 배치되어 있는지, MCP가 장치를 이름으로 찾을 수 있는지)을 5분 정도 넣는 것을 권장합니다.
  - 이 문서와 슬라이드는 1~2강에서 체크포인트, 결승선, 장애물이 배치된 상태를 전제로 썼습니다. 실제 1~2강 내용과 다르면 목표와 워크플로우 1번 문구를 맞춰야 합니다.
  - 장치 이름이 수강생마다 다를 수 있으므로, `find_actors`로 조회할 때 쓰는 이름 규칙을 1~2강에서 통일해 두면 3강이 편합니다.
- **혼자서도 확인할 수 있게 구성합니다**: 수강생 대부분이 혼자 연습하므로 2인 테스트가 필요한 항목(실시간 순위, 대기 표시)은 시연 영상이나 화면 캡처로 보여주고, 실습은 1인으로 확인 가능한 범위(타이머, 골인 기록, 결과 화면, 소리)로 잡는 편이 좋습니다.
- **코드가 길어서 완성본을 제공합니다**: `race_manager`는 500줄이 넘으므로 처음부터 따라 치게 하지 말고, 기능별로 나눈 단계별 파일(타이머 → 골인 → 진행도/순위 → 결과 화면)을 단계마다 제공하는 방식을 추천합니다.
- **시간이 부족하면**: 1~4번은 실습하고, 5~6번(결과 화면, 사운드)은 완성본을 보여주며 설명하는 방식을 추천합니다. 결과 화면 코드가 길고(이탤릭 글자 이미지 조립), 사운드는 wav 가져오기가 필요합니다.
- **사운드 실습 준비물**: 효과음 wav 파일을 수강생에게 배포하고, 가져오는 방법(Content Browser로 끌어다 놓기)을 영상으로 안내합니다. 이 프로젝트에서는 직접 만든 wav를 썼습니다.
- **미확인 항목**: 멀티플레이 동작, 모바일 화면 UI는 강의 전에 2인 테스트로 확인하기로 했습니다. 체크리스트는 `FallGuys_구조정리.md` 8장에 있습니다.
- **MCP의 한계 설명 포인트**: 게임을 직접 보거나 들을 수 없어서, 로그와 녹화 분석으로 확인했습니다. 소리가 안 났을 때 원인을 좁혀 가던 과정 자체가 좋은 사례입니다.
